# 7. A page per book

In this step you'll give every book a page of its own, at `/books/…` with the book's id, where you can
write notes about it and rate it. You'll add two columns to the table, declare a page that takes a
parameter, and link to it from the list.

Start from the project you finished in [step 6](06-load.md), with `k dev` running. The finished step is
in the repository as `examples/learn/shelf/07-routing`.

## Notes and a rating

Each book gets two more fields in the database: the reader's notes, and a rating from 1 to 5, with 0 for a
book that isn't rated yet. Add them to the end of `src/books/BookRecord.k`:

```k
// examples/learn/shelf/07-routing/src/books/BookRecord.k
// ...
    /// When the book was added, which orders the list.
    let addedAt: Date
    /// What the reader wrote about the book.
    var notes: String = ""
    /// From 1 to 5 stars, or 0 before the book is rated.
    var rating: Int = 0
}
```

The browser needs them too. Add the same two fields to `src/books/Book.k`:

```k
// examples/learn/shelf/07-routing/src/books/Book.k
// ...
    /// Who wrote it.
    let author: String
    /// What the reader wrote about the book.
    let notes: String = ""
    /// From 1 to 5 stars, or 0 before the book is rated.
    let rating: Int = 0
}
```

A field with a default can be left out where the struct is made, so `BookApi` still compiles. The defaults
matter for another reason too: `rpc.lock`, which `k build` writes, records what a `Book` looks like on the
wire, and a new field without a default would break a browser tab still running the old code. `k check`
reports that (`K8001`) rather than letting it ship.

Save, and the `k dev` terminal says the build failed:

```text
change detected; rebuilding
error: the project has 2 error(s); run `k check .` to see them
the last good build keeps serving
```

`k check` names them: `books.BookRecord.notes` and `books.BookRecord.rating` have no column in
`schema.lock` (`K8004`), as you saw in step 5. The table needs a migration. Run:

```console
$ k migrate new "add notes and ratings"
wrote migrations/0002_add_notes_and_ratings.k
wrote schema.lock
```

```k
// examples/learn/shelf/07-routing/migrations/0002_add_notes_and_ratings.k
// Generated by `k migrate new "add notes and ratings"` from the difference between
// the entities and schema.lock. Review it before committing.

/// Add notes and ratings.
migration AddNotesAndRatings {
    func up(schema: Schema) {
        schema.alterTable(name: "book_record") { table =>
            table.addColumn(name: "notes", type: .text)
                .defaultValue(.text(""))
            table.addColumn(name: "rating", type: .integer)
                .defaultValue(.integer(0))
        }
    }
}
```

This time the migration alters a table that already has rows: the books you added keep theirs, and get
the fields' defaults. `k dev` logs `applied migration 0002_add_notes_and_ratings` as it restarts.

## Ask for one book

The page will ask the server for one book by its id, and that can fail in a way the list can't: there may
be no such book. That's an error of the app's own, so declare it, in `src/books/LookupError.k`:

```k
// examples/learn/shelf/07-routing/src/books/LookupError.k
import k.rpc.RpcFailure

/// Why a call about one book failed.
public enum LookupError implements Error, Codable {
    /// There is no book with this id.
    case notFound

    /// The call didn't reach `BookApi`: the browser couldn't reach the
    /// server, for example.
    case rpcFailure(RpcFailure)
}
```

Every error an rpc throws has the `rpcFailure` case, for calls that never reach the server's code;
`RpcOnlyError`, from step 5, is the error with only that case. Next, the review form's value, in
`src/books/BookReview.k`, with the same kind of rules as `BookDraft`:

```k
// examples/learn/shelf/07-routing/src/books/BookReview.k
import k.validation.Length
import k.validation.Range
import k.validation.Validatable

/// What the review form asks for: notes, and a rating.
public struct BookReview implements Codable, Validatable {
    @Length(max: 2000)
    var notes: String

    @Range(0...5)
    var rating: Int
}
```

Add two rpcs to `src/books/BookProtocol.k`, one to get a book and one to save its review:

```k
// examples/learn/shelf/07-routing/src/books/BookProtocol.k
import k.crypto.Uuid
// ...
    /// Returns one book.
    ///
    /// - Throws: `LookupError.notFound` when there is no book with this id.
    rpc get(id: Uuid) throws LookupError -> Book
// ...

    /// Replaces a book's notes and rating.
    ///
    /// - Returns: the saved book.
    /// - Throws: `LookupError.notFound` when there is no book with this id.
    rpc review(id: Uuid, review: BookReview) throws LookupError -> Book
}
```

The repository finds a row by its id with `first`, which returns `nil` when no row matches. Add it to
`src/books/BookRepository.k`:

```k
// examples/learn/shelf/07-routing/src/books/BookRepository.k
import k.crypto.Uuid
// ...
    /// Returns the book with this id, or `nil` when there is none.
    func find(id: Uuid) async -> BookRecord? {
        return await bookRecords.first { record => record.id == id }
    }
}
```

Answer both rpcs in `src/books/BookApi.k`. The record-to-`Book` conversion is now needed four times, so
it moves into a private function at the end:

```k
// examples/learn/shelf/07-routing/src/books/BookApi.k
// ...
        return all.map { record => book(record: record) }
    }

    rpc get(id: Uuid) async throws LookupError -> Book {
        guard let record = await records.find(id: id) else {
            throw LookupError.notFound
        }

        return book(record: record)
    }
// ...
        return book(record: record)
    }

    rpc review(id: Uuid, review: BookReview) async throws LookupError -> Book {
        guard let record = await records.find(id: id) else {
            throw LookupError.notFound
        }

        var reviewed = record
        reviewed.notes = review.notes
        reviewed.rating = review.rating

        await records.update(reviewed)

        return book(record: reviewed)
    }

    /// The book the browser shows for a stored record.
    private func book(record: BookRecord) -> Book {
        return Book(
            id: record.id,
            title: record.title,
            author: record.author,
            notes: record.notes,
            rating: record.rating
        )
    }
}
```

- `guard let record = … else { … }` unwraps the optional, or leaves the function: after it, `record` is a
  `BookRecord`, not a `BookRecord?`.
- `throw LookupError.notFound` ends the call with that error, which reaches the browser as it is.
- An entity is a value: `var reviewed = record` is a copy you can change, and `update` writes it back.

Then give `src/books/BookService.k` the browser's side of both:

```k
// examples/learn/shelf/07-routing/src/books/BookService.k
import k.crypto.Uuid
// ...
    /// Loads one book from the server.
    ///
    /// - Throws: `LookupError.notFound` when there is no such book, and
    ///   `.rpcFailure` when the server can't be reached.
    func get(id: Uuid) async throws LookupError -> Book {
        return try await api.get(id: id)
    }
// ...
    /// Saves a book's notes and rating on the server.
    ///
    /// - Returns: the saved book.
    /// - Throws: `LookupError.notFound` when the book was deleted, and
    ///   `.rpcFailure` when the server can't be reached.
    func review(book: Book, review: BookReview) async throws LookupError -> Book {
        return try await api.review(id: book.id, review: review)
// ...
```

## A page with a parameter

Create the page, `src/books/BookDetails.k`:

```k
// examples/learn/shelf/07-routing/src/books/BookDetails.k
import k.crypto.Uuid

/// One book: its title and author, and the reader's notes and rating.
public page BookDetails at "/books/{id}" {
    /// The book to show, from the URL.
    @Param let id: Uuid

    @Inject let shelf: BookService

    @Load let book: Book = try await shelf.get(id: id)

    metadata {
        title("{book.title} · Shelf")
    }

    view {
        main {
            link(to: .home) { "All books" }

            heading(level: 1) { book.title }

            paragraph { "by {book.author}" }
                .class(.author)

            ReviewForm(book: book)
        }
        .class(.page)
    }

    loading {
        main {
            paragraph { "Loading the book…" }
        }
        .class(.page)
    }

    failed(let error) {
        main {
            match error {
                case .notFound {
                    metadata {
                        title("Book not found · Shelf")
                        status(.notFound)
                    }

                    paragraph { "This book isn't on your shelf." }
                }

                case .rpcFailure {
                    paragraph { "Shelf couldn't load this book." }

                    button { "Try again" }
                        .on(click: reload)
                }
            }

            link(to: .home) { "All books" }
        }
        .class(.page)
    }

    style {
        .page {
            maxWidth: 40rem;
            margin: 0 auto;
            padding: .lg;
            font: .body;
        }

        .author { color: .muted; }
    }
}
```

- `@Param let id: Uuid` is a page parameter: a value that comes from the URL. `at "/books/{id}"` says
  where it goes, so the page for a book is `/books/6f1c9b2e-…`. A URL whose id isn't a `Uuid` answers
  `404 Not Found` before the page runs.
- `link(to: .home)` is a link to another page. You never write the URL: every page is a case of a `Page`
  enum the compiler makes, `.home` for `Home` and `.bookDetails(id:)` for this one.
- In `failed`, the `.notFound` case adds to the page's `metadata`: `status(.notFound)` makes the server
  answer `404` for a book that doesn't exist, as it should, rather than `200` with an apology.

The form is a component of its own, `src/books/ReviewForm.k`. It starts from the book's saved notes and
rating, with `.empty(notes:rating:)`, and saves them through the service:

```k
// examples/learn/shelf/07-routing/src/books/ReviewForm.k
import k.validation.Form

/// The notes and rating of one book, and a button that saves them.
public component ReviewForm {
    @Inject let books: BookService

    /// The book to review, as it was loaded.
    @Prop let book: Book

    @Form var review: BookReview = .empty(notes: book.notes, rating: book.rating)
    @State var status: String? = nil

    func submit() async {
        status = nil

        do {
            try await books.review(book: book, review: review.value)

            status = "Saved."
        } catch .notFound {
            status = "This book isn't on the shelf any more."
        } catch .rpcFailure {
            status = "Couldn't save. Check your connection and try again."
        }
    }

    view {
        form {
            dropdown(selection: bind review.rating) {
                option(value: 0) { "Not rated" }

                for stars in [1, 2, 3, 4, 5] key stars {
                    option(value: stars) { "{stars} of 5" }
                }
            }
            .label("Rating")
            .class(.field)

            textArea(value: bind review.notes)
                .label("Notes")
                .rows(6)
                .class(.field)

            if let status {
                paragraph { status }
                    .role(.status)
            }

            button { "Save" }
                .type(.submit)
                .class(.save)
        }
        .class(.form)
        .on(submit: review.handle(submit))
    }

    style {
        .form {
            display: grid;
            gap: .sm;
        }

        .field {
            padding: .sm;
            border: 1px solid .border;
            borderRadius: .md;
            backgroundColor: .surface;
            color: .text;
        }

        .save {
            justifySelf: start;
            marginTop: .sm;
            padding: .sm .md;
            border: none;
            borderRadius: .md;
            backgroundColor: .primary;
            color: .onPrimary;
        }
    }
}
```

`dropdown` is a `<select>` whose options carry values of the bound field's type, here `Int`; `textArea` is
a text field of several lines. `.role(.status)` tells screen readers to announce the message when it
appears.

## Link to it

In `src/books/BookRow.k`, make each title a link to its book's page:

```k
// examples/learn/shelf/07-routing/src/books/BookRow.k
/// One book in the reading list: its title, which links to the book's
/// page, and who wrote it.
// ...
            link(to: .bookDetails(id: book.id)) { book.title }
// ...
```

Save, reload the start page and click a title. The book's page opens without a full page load: links
between pages of the app are followed in the browser, so the page loads its book there, and you may see
"Loading the book…" for a moment. That's the `loading` block step 6 promised. Rate the book, write a note,
click Save, then go back with **All books** and open it again: they're still there.

Run `k routes` to see every page and its URL:

```console
$ k routes
METHOD  URL          PAGE         PARAMS    GUARDS
GET     /            Home
GET     /books/{id}  BookDetails  id: Uuid
```

Then build once. `k build` writes the lockfiles that changed, `routes.lock` among them, which now records
the new URL:

```console
$ k build
wrote rpc.lock
wrote routes.lock
built dist
```

```toml
# Generated by `k build`. Add a redirect, or delete the entry of a URL
# that no longer needs to work; nothing else is edited by hand.
# Format: docs/design/12-routing.md

[pages.bookDetails]
declaration = "books.BookDetails"
url = "/books/{id}"

[pages.home]
declaration = "home.Home"
url = "/"
```

Commit it with the code. Once a URL is in `routes.lock`, a link someone saved keeps working, as the next
Try it shows.

**Try it:** link with the wrong value. In `BookRow.k`, change `book.id` to `book.title` in the link:

```text
error[K2001]: expected `k.crypto.Uuid`, found `String`
 --> src/books/BookRow.k:9:39
  |
9 |             link(to: .bookDetails(id: book.title)) { book.title }
  |                                       ^^^^^^^^^^

checked 20 files: 1 error(s), 0 warning(s)
```

A link names a page and its parameters with their types, so a link to a page that doesn't exist, or with
the wrong parameters, doesn't compile. Change it back.

**Try it:** move the page. Delete ` at "/books/{id}"` from the `page` line, so the page takes its URL from
its name, and run `k check`:

```text
error[K8007]: the URL of `books.BookDetails` changed from `/books/{id}` to `/book-details/{id}`, and nothing serves the old one
 --> src/books/BookDetails.k:4:13
  |
4 | public page BookDetails {
  |             ^^^^^^^^^^^
  |
  = note: a page without `at` takes its URL from its name and its required parameters
  = help: keep the URL with `at "/books/{id}"`, add a redirect under `[redirects]` in routes.lock (`"/books/{id}" = "<page case>"`), or delete the entry once no link to it needs to work

checked 20 files: 1 error(s), 0 warning(s)
```

Every link inside the app would follow the page to its new URL, but links outside it, in bookmarks and
messages, wouldn't. `routes.lock` remembers them. Put `at "/books/{id}"` back.

Then test the new page, in `src/books/BookDetails.test.k`. A test renders a page as `BookDetails(id: …)`,
with its parameters as arguments:

```k
// examples/learn/shelf/07-routing/src/books/BookDetails.test.k
import k.crypto.Uuid
import k.test.render

test BookDetails {
    @Inject let records: BookRepository
    @Inject let shelf: BookService

    test "the page shows the book" {
        let book = try await shelf.add(draft: BookDraft(title: "Piranesi", author: "Susanna Clarke"))

        let screen = render(BookDetails(id: book.id))
        await screen.settle()

        expect screen.heading(named: "Piranesi").isVisible
        expect screen.text("by Susanna Clarke").isVisible
        expect screen.link(named: "All books").isVisible
    }

    test "notes and a rating are saved on the server" {
        let book = try await shelf.add(draft: BookDraft(title: "Piranesi", author: "Susanna Clarke"))
        let screen = render(BookDetails(id: book.id))
        await screen.settle()

        screen.dropdown(labeled: "Rating").fill("4")
        screen.textArea(labeled: "Notes").fill("The house is the world.")
        screen.button(named: "Save").click()
        await screen.settle()

        expect screen.status().text == "Saved."

        let saved = await records.find(id: book.id)

        expect saved?.rating == 4
        expect saved?.notes == "The house is the world."
    }

    test "a book that doesn't exist isn't found" {
        let screen = render(BookDetails(id: Uuid.random()))
        await screen.settle()

        expect screen.text("This book isn't on your shelf.").isVisible
    }
}
```

`saved?.rating` reads `rating` if `saved` isn't `nil`, and is `nil` otherwise, so the expectation fails
rather than the test crashing when the book wasn't found.

## Recap

In this step you:

- added columns to a table that has rows, with a second migration;
- declared a page with a parameter, `@Param`, at a URL of your choosing with `at`;
- linked to it with `link(to:)` and a `Page` case, which the compiler checks;
- declared an error of your own, threw it on the server, and answered `404` for it;
- kept the page's URL in `routes.lock`, so links from outside the app keep working.
