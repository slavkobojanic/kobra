# Project files and lockfiles

## Files you write

| File | Purpose |
|---|---|
| `k.toml` | the manifest: package name, version, minimum toolchain version, dependencies, aliases |
| `App.k` | the `app` declaration; its presence makes a project an app rather than a library |
| `src/**/*.k` | source; each directory is a module |
| `src/**/*.test.k` | tests, next to the code they test |
| `migrations/NNNN_description.k` | database migrations (generated by `k migrate new`, then reviewed) |
| `.env` | local configuration for `k dev`; git-ignored |
| `.env.example` | documents what `.env` should contain; committed |

## `k.toml`

> **Proposal.** The manifest format follows `docs/design/proposals/k-toml.md`.

| Section | Contents |
|---|---|
| `[package]` | `name`, `version`, `description`, `k` (the minimum toolchain version). All but `description` are required. |
| `[dependencies]` | module path = git tag; edited by `k add` |
| `[aliases]` | short name = module path, enabling `import charts.LineChart` |

The manifest never holds environment variables, secrets, per-environment settings or tool options.

## Lockfiles

Lockfiles are generated by the toolchain and **committed**. Each records something that systems outside
your codebase depend on, and every build compares the code with the lock. A change that would break those
systems fails `k check`, unless it is marked as deliberate.

| Lockfile | Records | Protects | Deliberate break |
|---|---|---|---|
| `protocol.lock` | Protobuf field numbers of every protocol message | deployed clients, other-language clients | `@Breaking("reason")` on the protocol, which bumps its version |
| `routes.lock` | every page's URL, and redirects from old URLs | bookmarks, search engines, links in emails | renaming adds a permanent redirect automatically; conflicts are errors |
| `schema.lock` | the database schema the migrations produce | production data | `@Breaking("reason")` on a destructive migration |
| `k.lock` | the exact commit and content hash of every package | reproducible builds | `k add` with a new version |

### `protocol.lock`

The compiler assigns Protobuf field numbers so struct source stays clean. A removed field, a changed
type, or a reused number fails the check; a removed field's number is reserved automatically.

### `routes.lock`

Pages without a named URL get URLs derived from their names. When a page is renamed, its URL changes,
and the lock lets the compiler add a permanent redirect from the old one. Duplicate or conflicting URLs
are compile errors. `k routes` prints the table.

### `schema.lock`

> **Proposal.** The format follows `docs/design/proposals/migrations.md`.

`schema.lock` is TOML. It records the migrations applied so far and the resulting tables, so `k check`
can compare entities with the schema without a database:

```toml
# Generated by `k migrate`. Do not edit by hand.
migrations = ["0001_create_accounts_and_notes", "0002_add_note_pinning"]

[tables.note]
entity = "notes.Note"
columns = [
    { name = "id", type = "uuid", primaryKey = true },
    { name = "owner_id", type = "text", indexed = true },
    { name = "is_pinned", type = "boolean", default = false },
]
```

`k check` fails when the entities differ from the lock ("run `k migrate new`"), or when replaying the
migrations doesn't produce the lock.

### `k.lock`

Pins each package to a commit and a content hash, so a re-tagged release is detected rather than silently
used.

## Generated, never committed

| Path | Contents |
|---|---|
| `dist/` | build output: `dist/app` and `dist/public/` |
| `.k/` | the toolchain's local state, such as the development database and caches |
