# Project files and lockfiles

## Files you write

| File | Purpose |
|---|---|
| `k.toml` | the manifest: name, title, description, minimum toolchain version, dependencies, aliases |
| `App.k` | the `app` declaration; its presence makes a project an app rather than a library |
| `src/**/*.k` | source; each directory is a module |
| `src/**/*.test.k` | tests, next to the code they test |
| `src/**/testing/*.k` | shared fakes and fixtures, in test-only modules |
| `migrations/NNNN_description.k` | database migrations (written by `k migrate new`, then reviewed) |
| `.env` | local configuration for `k dev`; git-ignored |
| `.env.example` | documents what `.env` may contain, with placeholders only; committed |

## `k.toml`

| Section | Contents |
|---|---|
| `[package]` | `name` and `k` (the minimum toolchain version) are required. `title` and `description` are optional. Apps may set `version`; packages can't, because their git tag is their version. |
| `[dependencies]` | module path = git tag; edited by `k add` and `k remove` |
| `[aliases]` | short name = module path, enabling `import charts.LineChart` |

The manifest never holds environment variables, secrets, per-environment settings, build scripts or tool
options. See [Project layout](../getting-started/project-layout.md#ktoml).

## Lockfiles

Lockfiles are generated by the toolchain and **committed**. Each records something that systems outside
your codebase depend on, and every build compares the code with the lock. A change that would break those
systems fails `k check`, unless it is marked as deliberate.

| Lockfile | Records | Protects | Deliberate break |
|---|---|---|---|
| `protocol.lock` | Protobuf package, service and method names and field numbers of every protocol | deployed clients, other-language clients | `@Breaking("reason")` on the protocol, which bumps its version |
| `routes.lock` | every page's URL, endpoint pages included, and redirects from old URLs | bookmarks, search engines, links in emails, webhook senders | renaming adds a permanent redirect automatically; conflicts are errors |
| `schema.lock` | the database schema the migrations produce, with every table and column name, and the migration order | production data | `@Breaking("reason")` on a destructive migration |
| `storage.lock` | the browser storage namespace, `StorageKey` names and value shapes, and job names and payload shapes | users' stored data, jobs queued during a deploy | `@Breaking("reason")` on the key or job |
| `k.lock` | the exact commit and content hash of every package | reproducible builds | `k add` with a new version |

**A name that something outside depends on is recorded once and then kept.** Renaming the declaration it
came from, or the project, never silently changes it.

### `protocol.lock`

The compiler assigns Protobuf field numbers so struct source stays clean, and derives each protocol's
wire names from the project name, module, protocol and rpc names. A removed field, a changed type, a
reused number or a changed wire name fails the check; a removed field's number is reserved automatically.

### `routes.lock`

Pages without a named URL get URLs derived from their names. When a page is renamed, its URL changes,
and the lock lets the compiler add a permanent redirect from the old one. Duplicate or conflicting URLs
are compile errors. `k routes` prints the table.

### `schema.lock`

`schema.lock` is TOML. It records the migrations applied so far and the resulting tables, so `k check`
can compare entities with the schema without a database. Each column records the field it belongs to and
its locked name:

```toml
# Generated by `k migrate`. Do not edit by hand.
migrations = ["0001_create_accounts_and_notes", "0002_add_note_pinning"]

[tables.note]
entity = "notes.Note"
columns = [
    { field = "id", name = "id", type = "uuid", primaryKey = true },
    { field = "owner", name = "owner_id", type = "uuid", references = "account.id", indexed = true },
    { field = "title", name = "title", type = "text" },
    { field = "isPinned", name = "is_pinned", type = "boolean", default = false },
    { field = "revision", name = "revision", type = "integer", default = 1 },
]
```

- Enumeration columns record their cases, and money columns are one logical column of type `money`.
- A retired column keeps its name and has no field.
- `k check` fails when the entities differ from the lock ("run `k migrate new`"), when replaying the
  migrations doesn't produce the lock, or when file numbers don't match the `migrations` list.
- Standard-library tables (`k_session`, `k_job`, `k_rate_limit`) aren't recorded.

### `storage.lock`

`storage.lock` is TOML. It records the app's browser-storage namespace, derived from `k.toml`'s `name`
once, and for every `StorageKey` and every job its name, its declaration and the `Codable` shape of its
value or payload. Adding an optional field is compatible; any other change to a recorded shape needs
`@Breaking`. See [Local storage](../apps/local-storage.md#file-format) for the format, and
[Background jobs](../apps/jobs.md#stored-payloads).

### `k.lock`

Pins each package to a commit and a content hash, so a re-tagged release is detected rather than silently
used.

## Generated, never committed

| Path | Contents |
|---|---|
| `dist/` | build output: `dist/app` and `dist/public/` |
| `.k/` | the toolchain's local state, such as the development database and caches |
